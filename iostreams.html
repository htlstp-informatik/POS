Was ist ein I/O-Stream?

Ein Stream transportiert Daten sequentiell von einer Quelle zu einem Ziel, etwa einer Datei, einem Array oder einer Netzwerkverbindung. Input bedeutet Lesen, Output bedeutet Schreiben. I/O-Streams aus java.io sind nicht dasselbe wie die Stream API für Collections.

Datenquelle → InputStream → Java-Programm → OutputStream → Datensenke

Byte-Streams transportieren Bytes (Binärdaten), Character-Streams UTF-16-Codeeinheiten (Text).

Byte-Streams und Low-Level-Streams

InputStream und OutputStream sind abstrakte Basisklassen. FileInputStream und FileOutputStream greifen direkt auf Dateien zu; ByteArrayInputStream und ByteArrayOutputStream arbeiten im Speicher. PipedInputStream und PipedOutputStream verbinden zwei Streams.

Die folgenden Ausschnitte können in einer main-Methode mit throws IOException ausgeführt werden:

import java.io.*;
import java.nio.file.*;
import java.nio.charset.StandardCharsets;
import java.nio.ByteBuffer;
import java.util.*;
import java.util.zip.*;

public class Main {
    public static void main(String[] args) throws IOException {
        // Beispiel hier einfügen
    }
}

Einzelne Bytes schreiben und lesen

try (OutputStream out = new FileOutputStream("data.bin")) {
    out.write(65);
    out.write(255);
    out.write(0x12345678); // nur 0x78 = 120
}
try (InputStream in = new FileInputStream("data.bin")) {
    int b;
    while ((b = in.read()) != -1) {
        System.out.println(b); // 65, 255, 120
    }
}

read() liefert einen int von 0 bis 255 oder -1 am Ende. write(int) schreibt nur die niedrigsten 8 Bits. try-with-resources schließt die Ressourcen auch bei Exceptions. FileOutputStream überschreibt standardmäßig eine vorhandene Datei; mit true als zweitem Konstruktorparameter hängt er Daten an.

Blockweise kopieren

try (InputStream in = new FileInputStream("data.bin");
     OutputStream out = new FileOutputStream("copy.bin")) {
    byte[] buffer = new byte[4096];
    int n;
    while ((n = in.read(buffer)) != -1) {
        out.write(buffer, 0, n);
    }
}

read(buffer) liefert die tatsächlich gelesene Anzahl, nicht unbedingt die Arraylänge. Deshalb nur n Bytes schreiben. Bei einem Array mit 4096 Elementen können beispielsweise beim letzten Lesen nur noch 12 Bytes zurückgegeben werden.

Die wichtigsten Methoden von InputStream

MethodeBedeutung
read()Liest ein Byte als int (0 bis 255), am Ende -1.
read(byte[] b)Liest bis zu b.length Bytes; liefert die Anzahl oder -1.
read(byte[] b, int off, int len)Liest bis zu len Bytes in das Array ab Index off.
skip(long n)Überspringt bis zu n Bytes; liefert die tatsächlich übersprungene Anzahl.
available()Schätzt, wie viele Bytes ohne Blockieren gelesen werden können.
close()Schließt den Stream und gibt Ressourcen frei.

skip(): Bytes überspringen

skip(n) bewegt die Leseposition vorwärts, ohne die übersprungenen Bytes an das Programm zurückzugeben. Das ist beispielsweise nützlich, wenn ein Dateiformat einen Header enthält, den man nicht benötigt. Die Methode garantiert nicht, dass n Bytes übersprungen werden.

byte[] data = {10, 20, 30, 40, 50};
try (InputStream in = new ByteArrayInputStream(data)) {
    System.out.println(in.read());  // 10
    System.out.println(in.skip(2)); // 2 (20 und 30 übersprungen)
    System.out.println(in.read());  // 40
    System.out.println(in.skip(9)); // 1 (nur 50 übrig)
    System.out.println(in.read());  // -1
}

Mit skipNBytes(n) (seit Java 12) müssen genau n Bytes übersprungen werden; andernfalls wird eine EOFException geworfen.

mark(), reset() und markSupported()

mark(readlimit) merkt sich die aktuelle Leseposition. reset() springt zu dieser Position zurück. readlimit gibt an, wie viele Bytes nach der Markierung gelesen werden dürfen, bevor die Markierung ungültig werden kann. Eine neue Markierung ersetzt die alte. Nicht alle Streams unterstützen diese Methoden: FileInputStream beispielsweise nicht, BufferedInputStream hingegen schon.

try (InputStream in = new BufferedInputStream(
        new ByteArrayInputStream(new byte[] {10, 20, 30, 40, 50}))) {
    System.out.println(in.markSupported()); // true
    System.out.println(in.read()); // 10
    in.mark(3);                    // Position vor 20 merken
    System.out.println(in.read()); // 20
    System.out.println(in.read()); // 30
    in.reset();                    // zurück vor 20
    System.out.println(in.read()); // 20
}

Wozu? Beispielsweise kann man die ersten Bytes eines Dateiformats prüfen und anschließend dieselben Bytes erneut lesen. reset() kann eine IOException werfen, wenn keine gültige Markierung vorhanden ist. ByteArrayInputStream ignoriert das readlimit; bei BufferedInputStream kann die Marke nach Überschreiten des Limits verloren gehen.

available(): Lesen ohne Warten

available() liefert eine Schätzung der Anzahl der Bytes, die ohne Blockieren gelesen oder übersprungen werden können. Bei Netzwerkverbindungen kann der Wert 0 sein, obwohl später weitere Daten eintreffen. Daher ist available() weder ein allgemeiner EOF-Test noch eine zuverlässige Dateigröße.

try (InputStream in = new ByteArrayInputStream(new byte[] {10, 20, 30})) {
    System.out.println(in.available()); // 3
    in.read();
    System.out.println(in.available()); // 2
}

OutputStream: write(), flush() und close()

write(int) schreibt ein Byte; write(byte[]) schreibt das gesamte Array; write(byte[], off, len) schreibt len Bytes ab Arrayindex off. flush() gibt gepufferte Daten an den darunterliegenden Stream weiter. Das ist wichtig, wenn Daten sofort weitergegeben werden sollen, etwa bei einer Netzwerkverbindung. Es garantiert keine physische Speicherung auf dem Datenträger. close() schließt die Ressource; BufferedOutputStream leert dabei auch seinen Puffer.

try (OutputStream out = new BufferedOutputStream(
        new FileOutputStream("buffered.bin"))) {
    byte[] data = {10, 20, 30, 40};
    out.write(data, 1, 2); // schreibt 20 und 30
    out.flush();         // Puffer an FileOutputStream weitergeben
} // close() automatisch

Streams im Speicher

ByteArrayOutputStream out = new ByteArrayOutputStream();
out.write(new byte[] {65, 66, 67});
byte[] bytes = out.toByteArray();
try (InputStream in = new ByteArrayInputStream(bytes)) {
    System.out.println(in.read()); // 65
}

Filter-Streams und Decorator Pattern

Filter-Streams umwickeln andere Streams und ergänzen Funktionen wie Pufferung oder das Lesen primitiver Datentypen. Das Decorator Pattern nutzt Komposition: Ein Wrapper enthält eine Referenz auf einen anderen Stream. InputStream ist die Component, FileInputStream eine ConcreteComponent, FilterInputStream der Decorator und BufferedInputStream ein ConcreteDecorator.

FileInputStream → BufferedInputStream → DataInputStream → Programm

try (DataOutputStream out = new DataOutputStream(
        new BufferedOutputStream(new FileOutputStream("values.bin")))) {
    out.writeInt(42);       // 4 Bytes
    out.writeDouble(3.14);  // 8 Bytes
    out.writeUTF("Hallo"); // 2 Bytes Längenfeld + 5 Bytes
}
try (DataInputStream in = new DataInputStream(
        new BufferedInputStream(new FileInputStream("values.bin")))) {
    System.out.println(in.readInt());    // 42
    System.out.println(in.readDouble()); // 3.14
    System.out.println(in.readUTF());    // Hallo
}

Die Reihenfolge und Datentypen müssen beim Lesen und Schreiben übereinstimmen. DataInputStream und DataOutputStream implementieren DataInput und DataOutput. readInt(), readDouble() und readUTF() werfen bei unvollständigen Daten EOFException. writeUTF verwendet Modified UTF-8, nicht gewöhnliches UTF-8. Die numerischen Werte werden Big Endian gespeichert.

PrintStream

try (PrintStream out = new PrintStream("output.txt", StandardCharsets.UTF_8)) {
    out.println("Hallo");
    out.println(42); // Text, nicht binärer int
    System.out.println(out.checkError());
}

System.out ist ein PrintStream. PrintStream meldet Schreibfehler über checkError() statt über IOException bei print/println. BufferedInputStream unterstützt mark/reset; beim Schließen des äußeren Streams werden die darunterliegenden Streams geschlossen.

Character-Streams: Reader und Writer

Reader und Writer verarbeiten char-Werte (16 Bit). FileReader und FileWriter arbeiten mit Dateien; StringReader und StringWriter mit Strings. BufferedReader und BufferedWriter puffern Daten und bieten readLine() bzw. newLine().

try (Writer writer = new FileWriter("text.txt", StandardCharsets.UTF_8)) {
    writer.write("Hallo Welt!");
}
try (Reader reader = new FileReader("text.txt", StandardCharsets.UTF_8)) {
    int c;
    while ((c = reader.read()) != -1) {
        System.out.print((char) c);
    }
}

Reader.read() liefert 0 bis 65535 oder -1. Writer.write(int) schreibt nur die niedrigsten 16 Bits. Beide unterstützen Arrays mit Offset und Länge. ready() sagt, ob der nächste Lesevorgang nicht blockiert, nicht ob EOF erreicht ist.

Weitere Reader- und Writer-Methoden

Reader.skip(n) überspringt bis zu n UTF-16-Codeeinheiten und liefert die tatsächliche Anzahl. Reader.mark(readAheadLimit), reset() und markSupported() funktionieren analog zu den Byte-Streams, aber das Limit zählt char-Werte statt Bytes. BufferedReader unterstützt diese Methoden. ready() gibt an, ob der nächste Lesevorgang garantiert nicht blockiert; false bedeutet nicht zwingend Dateiende.

try (Reader reader = new BufferedReader(new StringReader("ABCDE"))) {
    System.out.println((char) reader.read()); // A
    reader.mark(3);
    System.out.println(reader.skip(2));       // 2 (B und C)
    System.out.println((char) reader.read()); // D
    reader.reset();
    System.out.println((char) reader.read()); // B
}

Writer.write(String, off, len) schreibt einen Teil eines Strings. flush() gibt gepufferte Zeichen weiter; close() schließt den Writer. Bei Textdateien bestimmt das Charset, wie viele Bytes ein Zeichen tatsächlich benötigt.

Zeilenweise mit Files

Path path = Path.of("text.txt");
try (BufferedWriter writer = Files.newBufferedWriter(path)) {
    writer.write("Erste Zeile");
    writer.newLine();
    writer.write("Zweite Zeile");
}
try (BufferedReader reader = Files.newBufferedReader(path)) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}

readLine() liefert null am Ende, eine leere Zeile dagegen als leeren String. Files.newBufferedReader und newBufferedWriter verwenden standardmäßig UTF-8. Files.readAllLines lädt alle Zeilen in den RAM. Für große Dateien ist zeilenweises Lesen sinnvoll. Mit CREATE und APPEND kann man Text anhängen:

try (BufferedWriter writer = Files.newBufferedWriter(Path.of("log.txt"),
        StandardOpenOption.CREATE, StandardOpenOption.APPEND)) {
    writer.write("Neuer Eintrag");
    writer.newLine();
}

Zeichensätze und Encoding

ASCII umfasst 128 Zeichen. ISO-8859-1 und ISO-8859-2 erweitern den Zeichenvorrat für unterschiedliche Sprachen. Unicode ordnet Zeichen Codepoints zu; UTF-8 und UTF-16 definieren deren Kodierung. Java-Strings verwenden logisch UTF-16-Codeeinheiten. Ein Emoji kann zwei char-Werte benötigen.

ZeichenCodepointUTF-8UTF-16
bU+00621 Byte2 Bytes
öU+00F62 Bytes2 Bytes
美U+7F8E3 Bytes2 Bytes
😊U+1F60A4 Bytes4 Bytes

Bei UTF-16 und UTF-32 ist die Byte-Reihenfolge relevant. Big Endian speichert das höchstwertige Byte zuerst, Little Endian das niedrigstwertige. Ein BOM kann die Reihenfolge kennzeichnen (UTF-16 BE: FE FF, LE: FF FE). UTF-8 benötigt kein BOM.

Bytes in Zeichen umwandeln

try (BufferedReader reader = new BufferedReader(
        new InputStreamReader(new FileInputStream("text.txt"),
                StandardCharsets.UTF_8))) {
    System.out.println(reader.readLine());
}
try (Writer writer = new OutputStreamWriter(
        new FileOutputStream("encoded.txt"), StandardCharsets.UTF_8)) {
    writer.write("Grüße 😊");
}

InputStreamReader dekodiert Bytes, OutputStreamWriter kodiert Zeichen. Das Charset muss zum Dateiformat passen. Seit Java 18 ist UTF-8 grundsätzlich das Standardcharset; explizite Angabe macht das Format eindeutig.

RandomAccessFile

RandomAccessFile erlaubt Lesen und Schreiben an beliebigen Bytepositionen. r öffnet nur zum Lesen, rw zum Lesen und Schreiben (erstellt bei Bedarf). rws synchronisiert Inhalt und Metadaten, rwd den Inhalt. seek(position) setzt den Dateizeiger, getFilePointer() liefert die aktuelle Position, length() die Dateilänge. setLength(0) leert eine vorhandene Datei.

try (RandomAccessFile file = new RandomAccessFile("ints.bin", "rw")) {
    file.setLength(0);
    file.writeInt(10);
    file.writeInt(20);
    file.writeInt(30);
    System.out.println(file.length()); // 12
    file.seek(4);
    System.out.println(file.readInt()); // 20
    System.out.println(file.getFilePointer()); // 8
    file.seek(4);
    file.writeInt(99); // zweiten Wert überschreiben
}

Bei Datensätzen fixer Länge gilt: Position = Index × Datensatzlänge (Index beginnt bei 0). Beispiel: 4 Bytes Katalognummer, je 15 char für Vor- und Zuname (je 30 Bytes), 1 Byte Geschlecht ergeben 65 Bytes. Bei einem Header muss dessen Länge zusätzlich berücksichtigt werden.

Arbeiten mit byte[]

byte b = (byte) 255;
System.out.println(b); // -1
System.out.println(Byte.toUnsignedInt(b)); // 255
byte[] data = ByteBuffer.allocate(4).putInt(42).array();
System.out.println(ByteBuffer.wrap(data).getInt()); // 42
try (DataInputStream in = new DataInputStream(new ByteArrayInputStream(data))) {
    System.out.println(in.readInt()); // 42
}

Java-byte ist signed (-128 bis 127). ByteBuffer interpretiert binäre Daten standardmäßig Big Endian. Die Textbytes von "42" sind nicht die binäre Darstellung des int 42.

Übungen

1. CheckInt

Eine Binärdatei enthält einen Kontrollinteger und anschließend ausschließlich doubles. Implementiere mit RandomAccessFile die Methoden createFile(String filename, double... values), isValidFile(String filename), getFileInfo(String filename) und append(String filename, double toAppend), jeweils mit throws IOException. Der Kontrollinteger muss der Anzahl der Doublewerte entsprechen. getFileInfo liefert beispielsweise:

Saved values: 5
1,20 7,80 3,50 6,80 4,50

append hängt einen Wert an und erhöht den Kontrollinteger.

Ein int benötigt 4 Bytes, ein double 8. Prüfe die Länge gegen 4 + 8L * count. Mit seek(0) kannst du den Header aktualisieren.

import java.io.*;
import java.util.*;

public class CheckInt {
    public static void createFile(String filename, double... values) throws IOException {
        try (RandomAccessFile f = new RandomAccessFile(filename, "rw")) {
            f.setLength(0);
            f.writeInt(values.length);
            for (double value : values) f.writeDouble(value);
        }
    }
    private static boolean valid(RandomAccessFile f) throws IOException {
        if (f.length() < 4) return false;
        f.seek(0);
        int count = f.readInt();
        return count >= 0 && f.length() == 4 + 8L * count;
    }
    public static boolean isValidFile(String filename) throws IOException {
        try (RandomAccessFile f = new RandomAccessFile(filename, "r")) {
            return valid(f);
        }
    }
    public static String getFileInfo(String filename) throws IOException {
        try (RandomAccessFile f = new RandomAccessFile(filename, "r")) {
            if (!valid(f)) throw new IllegalArgumentException("Ungültige Datei");
            f.seek(0);
            int count = f.readInt();
            StringBuilder result = new StringBuilder("Saved values: " + count + "\n");
            for (int i = 0; i < count; i++) {
                if (i > 0) result.append(' ');
                result.append(String.format(Locale.GERMANY, "%.2f", f.readDouble()));
            }
            return result.toString();
        }
    }
    public static void append(String filename, double toAppend) throws IOException {
        try (RandomAccessFile f = new RandomAccessFile(filename, "rw")) {
            if (!valid(f)) throw new IllegalArgumentException("Ungültige Datei");
            f.seek(0);
            int count = f.readInt();
            if (count == Integer.MAX_VALUE) throw new IllegalArgumentException("Zu viele Werte");
            f.seek(f.length());
            f.writeDouble(toAppend);
            f.seek(0);
            f.writeInt(count + 1);
        }
    }
    public static void main(String[] args) throws IOException {
        createFile("check.bin", 1.2, 7.8, 3.5, 6.8, 4.5);
        System.out.println(isValidFile("check.bin")); // true
        System.out.println(getFileInfo("check.bin"));
        append("check.bin", 9.1);
        System.out.println(getFileInfo("check.bin"));
    }
}

2. Numbers

Die Datei enthält wiederholt ein Typbyte (0 = int, 1 = double) und den zugehörigen Wert. Implementiere getContents(String filename) als List<Number>, groupByType(List<? extends Number> numbers) als Map<String, Set<Number>>, isValidFile(String filename) und createFile(String filename, List<Number> values). Ungültige Formate führen bei getContents zu IllegalArgumentException. Die Gruppen werden nach Subklassennamen gebildet und aufsteigend sortiert, z. B. {Double=[2.71, 3.14], Integer=[42, 100]}.

Lies das Typbyte mit read(): -1 ist reguläres EOF. EOFException beim anschließenden Wert bedeutet dagegen einen unvollständigen Datensatz. Verwende TreeMap und TreeSet.

import java.io.*;
import java.util.*;

public class Numbers {
    public static List<Number> getContents(String filename) throws IOException {
        List<Number> result = new ArrayList<>();
        try (DataInputStream in = new DataInputStream(
                new BufferedInputStream(new FileInputStream(filename)))) {
            int tag;
            while ((tag = in.read()) != -1) {
                try {
                    if (tag == 0) result.add(in.readInt());
                    else if (tag == 1) result.add(in.readDouble());
                    else throw new IllegalArgumentException("Unbekannter Typ: " + tag);
                } catch (EOFException e) {
                    throw new IllegalArgumentException("Unvollständiger Wert", e);
                }
            }
        }
        return result;
    }
    public static Map<String, Set<Number>> groupByType(List<? extends Number> numbers) {
        Map<String, Set<Number>> result = new TreeMap<>();
        for (Number n : numbers) {
            result.computeIfAbsent(n.getClass().getSimpleName(),
                    key -> new TreeSet<>()).add(n);
        }
        return result;
    }
    public static boolean isValidFile(String filename) throws IOException {
        try {
            getContents(filename);
            return true;
        } catch (IllegalArgumentException e) {
            return false;
        }
    }
    public static void createFile(String filename, List<Number> values) throws IOException {
        for (Number n : values) {
            if (!(n instanceof Integer) && !(n instanceof Double))
                throw new IllegalArgumentException("Nur Integer und Double erlaubt");
        }
        try (DataOutputStream out = new DataOutputStream(
                new BufferedOutputStream(new FileOutputStream(filename)))) {
            for (Number n : values) {
                if (n instanceof Integer i) {
                    out.writeByte(0);
                    out.writeInt(i);
                } else {
                    out.writeByte(1);
                    out.writeDouble(n.doubleValue());
                }
            }
        }
    }
    public static void main(String[] args) throws IOException {
        createFile("numbers.bin", List.of(42, 3.14, 100, 2.71));
        System.out.println(groupByType(getContents("numbers.bin")));
        // {Double=[2.71, 3.14], Integer=[42, 100]}
    }
}

Hinweis zur Lösung: TreeSet entfernt Duplikate. Die natürliche Ordnung funktioniert hier, weil jede Gruppe ausschließlich Integer oder ausschließlich Double enthält. Eine leere Datei gilt als gültige leere Sequenz.

3. DecoratorPattern

Entpacke eine GZIP-Datei (example.gz, die du dir vorher erstellt hast) und gib den Inhalt in Großbuchstaben aus. Verwende die vorgegebene Kette: FileInputStream → GZIPInputStream → BufferedInputStream → UpperCaseFilterInputStream. Implementiere UpperCaseFilterInputStream selbst.

Für diese Byte-Filter-Übung beschränken wir die Umwandlung auf ASCII-Buchstaben a–z. Für beliebigen Unicode-Text wäre ein Reader mit passender Dekodierung nötig.

Erweitere FilterInputStream. Überschreibe read() und read(byte[], int, int), damit auch blockweises Lesen umgewandelt wird. EOF muss -1 bleiben.

import java.io.*;
import java.nio.charset.StandardCharsets;
import java.util.zip.*;

public class DecoratorPattern {
    static class UpperCaseFilterInputStream extends FilterInputStream {
        UpperCaseFilterInputStream(InputStream in) {
            super(in);
        }
        private int upper(int b) {
            return b >= 'a' && b <= 'z' ? b - 'a' + 'A' : b;
        }
        @Override
        public int read() throws IOException {
            return upper(in.read());
        }
        @Override
        public int read(byte[] b, int off, int len) throws IOException {
            int n = in.read(b, off, len);
            for (int i = off; i < off + n; i++) {
                b[i] = (byte) upper(Byte.toUnsignedInt(b[i]));
            }
            return n;
        }
    }
    public static void main(String[] args) throws IOException {
        // Testdatei erstellen
        try (OutputStream out = new GZIPOutputStream(
                new FileOutputStream("example.gz"))) {
            out.write("Hallo Welt!".getBytes(StandardCharsets.UTF_8));
        }
        try (InputStream file = new FileInputStream("example.gz");
             InputStream gzip = new GZIPInputStream(file);
             InputStream buffered = new BufferedInputStream(gzip);
             InputStream upper = new UpperCaseFilterInputStream(buffered)) {
            upper.transferTo(System.out); // HALLO WELT!
        }
    }
}
