Java Path & Files

Pfade, Dateien und Verzeichnisse mit Java bearbeiten

Was sind Path und Files?

Mit Path und Files aus java.nio.file kannst du Dateien und Verzeichnisse unabhängig vom Betriebssystem bearbeiten. Ein Path beschreibt einen Pfad; Files führt Operationen im Dateisystem aus.

Path path = Path.of("example.txt");
System.out.println(Files.exists(path));

Das Erzeugen eines Path-Objekts legt noch keine Datei an. Die Beispiele verwenden Java 21.

File, Path und Files

java.io.File ist die ältere API und nicht deprecated. Path ist ein Interface; Paths ist eine Hilfsklasse. Heute bevorzugen wir Path.of() und die statischen Methoden von Files. Diese bieten unter anderem detaillierte Exceptions, Dateiattribute und Unterstützung für symbolische Links.

File file = new File("example.txt");
Path path = file.toPath();
File oldFile = path.toFile();

Imports und IOException

Viele Dateioperationen können eine IOException auslösen, etwa bei fehlenden Dateien oder fehlenden Zugriffsrechten. Für die folgenden Ausschnitte kannst du diese main-Methode verwenden.

import java.io.*;
import java.nio.file.*;
import java.nio.file.attribute.*;
import java.util.*;
import java.util.stream.*;

public class Main {
    public static void main(String[] args) throws IOException {
        // Beispiel hier einfügen
    }
}

Pfade erstellen und bearbeiten

Relative Pfade beziehen sich auf das Arbeitsverzeichnis des Programms. Absolute Pfade beginnen an einer Wurzel. Unter Windows ist beispielsweise C:/ ein Laufwerkswurzelpfad. Verwende einzelne Pfadsegmente für portable Beispiele.

Path path = Path.of("src", "main", "java", "Main.java");
Path same = Path.of("src/main/java").resolve("Main.java");
System.out.println(path.toAbsolutePath());
System.out.println(path.getRoot());      // null (relativ)
System.out.println(path.getParent());    // src/main/java
System.out.println(path.getFileName());  // Main.java
System.out.println(path.getName(0));     // src
System.out.println(path.getNameCount()); // 4
System.out.println(path.subpath(1, 3));  // main/java
System.out.println(path.startsWith("src")); // true
System.out.println(path.endsWith("Main.java")); // true

Die Ausgabe der Trennzeichen hängt vom Betriebssystem ab. subpath schließt den Endindex aus. startsWith und endsWith vergleichen vollständige Pfadsegmente.

Path src = Path.of("src/main");
Path java = src.resolve("java/at/htlstp");
System.out.println(src.relativize(java)); // java/at/htlstp
System.out.println(java.relativize(src)); // ../../..
System.out.println(Path.of("src/../data").normalize()); // data

relativize berechnet den Weg vom ersten zum zweiten Pfad. Beide müssen kompatibel sein (z. B. beide relativ). resolve liefert bei einem absoluten zweiten Pfad diesen zurück. normalize entfernt überflüssige Pfadsegmente, ohne das Dateisystem zu prüfen.

Existenz und Dateieigenschaften

Path path = Path.of("example.txt");
if (Files.exists(path)) {
    System.out.println(Files.isRegularFile(path));
    System.out.println(Files.isDirectory(path));
    System.out.println(Files.isReadable(path));
    System.out.println(Files.isWritable(path));
    System.out.println(Files.isExecutable(path));
    System.out.println(Files.getLastModifiedTime(path));
    if (Files.isRegularFile(path)) {
        System.out.println(Files.size(path) + " Bytes");
    }
}

Files.exists kann auch false liefern, wenn die Existenz nicht ermittelt werden kann. Die Größe einer regulären Datei wird in Bytes angegeben.

BasicFileAttributes attr = Files.readAttributes(
        Path.of("example.txt"), BasicFileAttributes.class);
System.out.println(attr.size());
System.out.println(attr.creationTime());
System.out.println(attr.lastModifiedTime());

Dateien vergleichen

isSameFile prüft, ob zwei Pfade dieselbe Datei bezeichnen. mismatch vergleicht den Inhalt: -1 bedeutet identisch, sonst wird der Index des ersten unterschiedlichen Bytes geliefert. getOwner liefert den Besitzer, sofern unterstützt.

Path a = Path.of("example.txt");
Path b = Path.of("copy.txt");
System.out.println(Files.isSameFile(a, b));
System.out.println(Files.mismatch(a, b));
System.out.println(Files.getOwner(a).getName());

Dateien und Verzeichnisse erstellen, kopieren, verschieben und löschen

Verwende für dieses Beispiel ein leeres Übungsverzeichnis. createDirectories erzeugt auch fehlende Elternverzeichnisse; createFile erzeugt eine leere Datei und schlägt fehl, wenn sie bereits existiert.

Path dir = Files.createDirectories(Path.of("demo"));
Path file = Files.createFile(dir.resolve("test.txt"));
Path copy = Files.copy(file, dir.resolve("copy.txt"));
Path moved = Files.move(copy, dir.resolve("moved.txt"));
Files.delete(moved);
Files.delete(file);
Files.delete(dir);

copy und move überschreiben standardmäßig keine vorhandenen Ziele. Mit StandardCopyOption.REPLACE_EXISTING erlaubst du das Überschreiben. copy kopiert ein Verzeichnis ohne Inhalt; move verschiebt ein Verzeichnis normalerweise samt Inhalt, sofern das Dateisystem dies unterstützt. Bei einem Wechsel des Dateisystems kann ein nicht leeres Verzeichnis nicht ohne Weiteres verschoben werden. COPY_ATTRIBUTES übernimmt unterstützte Attribute beim Kopieren; ATOMIC_MOVE fordert eine atomare Verschiebung an. delete löscht nur leere Verzeichnisse; deleteIfExists liefert false, wenn der Eintrag fehlt.

Temporäre Dateien

Path temp = Files.createTempFile("pos-", ".txt");
Path tempDir = Files.createTempDirectory("pos-");
System.out.println(temp);
Files.delete(temp);
Files.delete(tempDir);

Temporäre Dateien werden nicht automatisch beim Programmende gelöscht. Ohne explizites Verzeichnis wird das Standard-Temp-Verzeichnis verwendet.

Textdateien lesen und schreiben

Path path = Path.of("example.txt");
Files.writeString(path, "Hallo Java!\nZweite Zeile");
String text = Files.readString(path);
List<String> lines = Files.readAllLines(path);
System.out.println(text);
lines.forEach(System.out::println);

readAllLines liefert eine Liste mit einer Zeichenkette pro Zeile. readString liest den gesamten Text. Beide verwenden standardmäßig UTF-8. writeString erstellt die Datei oder überschreibt ihren Inhalt. Für große Dateien eignet sich Files.lines mit try-with-resources.

try (Stream<String> lines = Files.lines(Path.of("example.txt"))) {
    lines.forEach(System.out::println);
}

Verzeichnisse durchsuchen

Files.list liefert die direkten Einträge, Files.walk durchsucht auch Unterverzeichnisse und enthält den Startpfad. Beide liefern einen Stream, der geschlossen werden muss.

Path dir = Path.of(".");
try (Stream<Path> paths = Files.list(dir)) {
    paths.forEach(System.out::println);
}
try (Stream<Path> paths = Files.walk(dir)) {
    paths.filter(Files::isRegularFile)
         .forEach(System.out::println);
}

Glob-Muster

Ein Glob ist ein Suchmuster für Pfade: * steht für beliebig viele Zeichen innerhalb eines Segments, ** kann Verzeichnisgrenzen überschreiten, ? steht für ein Zeichen, [0-9] für eine Ziffer und {java,xml} für Alternativen.

PathMatcher matcher = FileSystems.getDefault()
        .getPathMatcher("glob:*.{java,xml,pdf}");
try (Stream<Path> paths = Files.walk(Path.of("."))) {
    paths.filter(Files::isRegularFile)
         .filter(p -> matcher.matches(p.getFileName()))
         .forEach(System.out::println);
}

Der Vergleich mit getFileName prüft nur den Dateinamen, unabhängig von der Verzeichnistiefe. Ein PathMatcher kann auch regex-Muster verwenden.

Files.find

find prüft Pfad und Dateiattribute mit einem BiPredicate. Die maximale Tiefe 0 umfasst nur den Startpfad.

try (Stream<Path> paths = Files.find(Path.of("."), 5,
        (p, attr) -> attr.isRegularFile()
                && p.getFileName().toString().endsWith(".java"))) {
    paths.forEach(System.out::println);
}

FileVisitor und walkFileTree

FileVisitor<Path> ermöglicht es, bei der rekursiven Suche auf einzelne Ereignisse zu reagieren. Die vier Methoden liefern FileVisitResult.

  • preVisitDirectory: vor dem Betreten des Verzeichnisses
  • visitFile: beim Besuch einer Datei
  • visitFileFailed: wenn ein Eintrag nicht besucht werden kann
  • postVisitDirectory: nach der Verarbeitung des Verzeichnisses

CONTINUE setzt die Suche fort, SKIP_SUBTREE überspringt bei preVisitDirectory den Inhalt, SKIP_SIBLINGS überspringt weitere Geschwister, TERMINATE beendet die Suche. SimpleFileVisitor bietet Standardimplementierungen; Fehler werden standardmäßig weitergeworfen.

Files.walkFileTree(Path.of("."), new SimpleFileVisitor<Path>() {
    @Override
    public FileVisitResult visitFile(Path file,
            BasicFileAttributes attrs) {
        System.out.println(file);
        return FileVisitResult.CONTINUE;
    }
});

Übungen

Die folgenden vier Aufgaben stammen aus dem Übungsblatt. Verwende ein eigenes Übungsverzeichnis und passe die Pfade an. Die Lösungen sind mögliche Umsetzungen.

1. Einen Pfad erstellen und Dateieigenschaften ausgeben

  • Erstelle einen Pfad zu example.txt.
  • Prüfe, ob die Datei existiert.
  • Gib die Dateigröße aus, falls eine reguläre Datei existiert.
  • Prüfe, ob es sich um eine Datei oder ein Verzeichnis handelt.

Verwende Path.of, Files.exists, Files.size, Files.isRegularFile und Files.isDirectory.

Path path = Path.of("example.txt");
System.out.println("Existiert: " + Files.exists(path));
if (Files.exists(path)) {
    System.out.println("Datei: " + Files.isRegularFile(path));
    System.out.println("Verzeichnis: " + Files.isDirectory(path));
    if (Files.isRegularFile(path)) {
        System.out.println("Größe: " + Files.size(path));
    }
}

2. Verzeichnisse und Dateien erstellen

  • Erstelle TestDir und darin test.txt.
  • Gib Größe, Erstellungszeit und letzte Modifikation aus.
  • Verschiebe test.txt nach NewDir und überprüfe den Erfolg.
  • Lösche die erstellte Datei und beide Verzeichnisse und überprüfe den Erfolg.

TestDir und NewDir dürfen für diese Lösung noch nicht existieren.

Nutze createDirectory, createFile, readAttributes, move und delete. Lösche zuerst die Datei, dann die Verzeichnisse.

Path testDir = Files.createDirectory(Path.of("TestDir"));
Path file = Files.createFile(testDir.resolve("test.txt"));
BasicFileAttributes attr = Files.readAttributes(
        file, BasicFileAttributes.class);
System.out.println("Größe: " + attr.size());
System.out.println("Erstellt: " + attr.creationTime());
System.out.println("Geändert: " + attr.lastModifiedTime());
Path newDir = Files.createDirectory(Path.of("NewDir"));
Path target = Files.move(file, newDir.resolve("test.txt"));
System.out.println("Verschoben: " +
        (Files.notExists(file) && Files.isRegularFile(target)));
Files.delete(target);
Files.delete(testDir);
Files.delete(newDir);
System.out.println("Gelöscht: " + (Files.notExists(target)
        && Files.notExists(testDir) && Files.notExists(newDir)));

3. Dateiinhalt lesen und ausgeben

Lies die Datei .gitignore mit readAllLines in eine Liste ein und gib die Liste aus. Die Datei muss im Arbeitsverzeichnis vorhanden sein.

readAllLines liefert List<String>. Verwende println für die Liste oder forEach für einzelne Zeilen.

Path path = Path.of(".gitignore");
List<String> lines = Files.readAllLines(path);
System.out.println(lines);
lines.forEach(System.out::println);

4. Datei mit FileVisitor suchen

Implementiere FileVisitor und suche rekursiv nach einer Datei, z. B. FileSearchExample.java. Verwende Files.walkFileTree mit einem selbst gewählten Startverzeichnis. Gib bei Erfolg „File <Datei> gefunden“ aus, sonst „File <Datei> not found“.

Speichere den Suchnamen und ein boolean found. Vergleiche in visitFile den Dateinamen und beende bei einem Treffer mit TERMINATE. Prüfe found nach walkFileTree.

import java.io.IOException;
import java.nio.file.*;
import java.nio.file.attribute.BasicFileAttributes;

public class FileSearchExample implements FileVisitor<Path> {
    private final String fileToSearch;
    private boolean found;

    public FileSearchExample(String fileToSearch) {
        this.fileToSearch = fileToSearch;
    }

    @Override
    public FileVisitResult preVisitDirectory(Path dir,
            BasicFileAttributes attrs) {
        return FileVisitResult.CONTINUE;
    }

    @Override
    public FileVisitResult visitFile(Path file,
            BasicFileAttributes attrs) {
        if (attrs.isRegularFile() &&
                file.getFileName().toString().equals(fileToSearch)) {
            found = true;
            System.out.println("File " + file + " gefunden");
            return FileVisitResult.TERMINATE;
        }
        return FileVisitResult.CONTINUE;
    }

    @Override
    public FileVisitResult visitFileFailed(Path file,
            IOException exc) throws IOException {
        throw exc;
    }

    @Override
    public FileVisitResult postVisitDirectory(Path dir,
            IOException exc) throws IOException {
        if (exc != null) throw exc;
        return FileVisitResult.CONTINUE;
    }

    public static void main(String[] args) throws IOException {
        Path startingDir = Path.of("."); // anpassen
        String fileToSearch = "FileSearchExample.java";
        FileSearchExample crawler = new FileSearchExample(fileToSearch);
        Files.walkFileTree(startingDir, crawler);
        if (!crawler.found) {
            System.out.println("File " + fileToSearch + " not found");
        }
    }
}

Bei einem Zugriffsfehler wird die IOException weitergegeben, damit eine unvollständige Suche nicht fälschlich als „not found“ ausgegeben wird. Als kürzere Variante kann die Klasse SimpleFileVisitor erweitert werden.
