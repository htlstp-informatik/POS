Was ist das Java Collections Framework?

Das Java Collections Framework stellt Interfaces und Klassen bereit, mit denen Gruppen von Objekten gespeichert und verarbeitet werden können. Generics legen dabei fest, welcher Elementtyp erlaubt ist.

List<String> namen = new ArrayList<>();
namen.add("Anna");
namen.add("Max");

Je nach Anforderung verwendet man unterschiedliche Datenstrukturen: Listen, Mengen oder Zuordnungen von Schlüsseln zu Werten.

Überblick über das Collections Framework

Iterable<E>
   └── Collection<E>
       ├── List<E>
       │   └── ArrayList<E>
       ├── Set<E>
       │   ├── HashSet<E>
       │   ├── LinkedHashSet<E>
       │   └── SortedSet<E>
       │       └── NavigableSet<E>
       │           └── TreeSet<E>
       └── Queue<E>

Map<K,V>                 // gehört NICHT zu Collection
   ├── HashMap<K,V>
   ├── LinkedHashMap<K,V>
   └── TreeMap<K,V>

Collection<E> ist das zentrale Interface für Sammlungen einzelner Elemente. Map<K,V> gehört zwar zum Collections Framework, ist aber keine Unterklasse bzw. kein Unterinterface von Collection.

Das Interface Collection<E>

E steht für den Elementtyp. Bei Collection<String> ist also E = String.

public interface Collection<E> extends Iterable<E> {
    int size();
    boolean isEmpty();
    boolean contains(Object o);
    Iterator<E> iterator();
    boolean add(E e);
    boolean remove(Object o);
    boolean containsAll(Collection<?> c);
    boolean addAll(Collection<? extends E> c);
    void clear();
}

Warum bei addAll <? extends E>?

Collection<Number> zahlen = new ArrayList<>();
Collection<Integer> ganzeZahlen = List.of(1, 2, 3);

zahlen.addAll(ganzeZahlen);

Bei Collection<Number> ist der Typparameter E = Number. Die Signatur addAll(Collection<? extends E> c) wird damit gedanklich zu addAll(Collection<? extends Number> c).

Generische Typen sind in Java invariant: Ein Integer ist zwar ein Number, aber Collection<Integer> ist keine Collection<Number>. Durch <? extends E> darf addAll trotzdem Collections von E oder Untertypen von E übernehmen.

Warum contains(Object) und remove(Object)?

contains(Object o) und remove(Object o) akzeptieren bewusst ein beliebiges Object. Damit kann geprüft werden, ob ein beliebiges Objekt in der Collection enthalten ist bzw. ein dazu gleiches Element entfernt werden.

Collection<String> namen = new ArrayList<>();
namen.add("Anna");

System.out.println(namen.contains("Anna")); // true
System.out.println(namen.contains(42));     // false
System.out.println(namen.remove("Anna"));  // true
System.out.println(namen.remove(42));       // false

remove(Object) liefert true, wenn ein passendes Element gefunden und entfernt wurde, sonst false. Die mögliche Verwechslung mit remove(int index) betrifft erst List, nicht das Interface Collection.

List und ArrayList

Eine List speichert Elemente in einer Reihenfolge. Duplikate sind erlaubt und auf Elemente kann über einen Index zugegriffen werden.

List<String> namen = new ArrayList<>();
namen.add("Anna");
namen.add("Max");
namen.add("Anna");

System.out.println(namen.get(1)); // Max
System.out.println(namen.size()); // 3
  • Reihenfolge bleibt erhalten
  • Duplikate sind erlaubt
  • Zugriff über Index
  • ArrayList: schneller wahlfreier Zugriff

remove(int) oder remove(Object)?

List überlädt remove(). Bei einer List<Integer> ist deshalb besonders auf den Parametertyp zu achten.

List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 2, 4));

nums.remove(2);                  // int → Index 2, entfernt 3
nums.remove(Integer.valueOf(2)); // Integer → entfernt den Wert 2

Arrays.asList(): Liste mit fixer Größe

String[] a = {"x", "y", "z"};
List<String> list = Arrays.asList(a);

a[1] = "Y";
System.out.println(list); // [x, Y, z]

list.add("w"); // UnsupportedOperationException

Die von Arrays.asList() erzeugte Liste ist mit dem Array verbunden und hat eine fixe Größe. Elemente können mit set() ersetzt werden, aber add() und remove() sind nicht möglich.

Iterator und ListIterator

Während einer Iteration sollte die Collection nicht direkt strukturell verändert werden. Eine for-each-Schleife verwendet intern einen Iterator. Wird die Liste währenddessen direkt mit list.remove() verändert, kann der Iterator beim nächsten Zugriff eine ConcurrentModificationException auslösen.

// FALSCH:
for (String s : list) {
    if (s.length() < 5) {
        list.remove(s); // direkte Änderung während der Iteration
    }
}

Zum sicheren Löschen wird die Änderung über denselben Iterator durchgeführt:

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().length() < 5) {
        it.remove();
    }
}

ListIterator bietet für Listen zusätzliche Möglichkeiten: Es kann vorwärts und rückwärts laufen sowie mit add() Elemente während des Durchlaufens einfügen und mit set() ersetzen.

Set

Ein Set speichert jedes Element höchstens einmal. Wie Gleichheit und Reihenfolge bestimmt werden, hängt von der Implementierung ab.

Set<String> namen = new HashSet<>();
namen.add("Anna");
namen.add("Max");
namen.add("Anna");

System.out.println(namen.size()); // 2

Wichtige Set-Implementierungen

  • HashSet: Hashing, keine garantierte Reihenfolge
  • LinkedHashSet: Hashing + Einfügereihenfolge
  • TreeSet: sortiert nach natürlicher Ordnung oder Comparator

Hashing

Grundidee

Objekt / Key
     ↓
 hashCode()
     ↓
Bucket bestimmen
     ↓
Hashwert vergleichen
     ↓
bei gleichem Hashwert:
   equals()

Der Hashcode hilft dabei, den Suchbereich stark einzuschränken. Mehrere Elemente dürfen im selben Bucket liegen. Haben Kandidaten denselben Hashwert, entscheidet equals(), ob sie tatsächlich gleich sind.

Hash-Kollision

a.hashCode() == b.hashCode()
a.equals(b) == false

Das ist eine Hash-Kollision: Zwei verschiedene Objekte besitzen denselben Hashcode. Beide dürfen gespeichert werden.

Vertrag von equals() und hashCode()

a.equals(b) == true
→ a.hashCode() == b.hashCode()   // muss gelten

a.hashCode() == b.hashCode()
→ a.equals(b) kann true oder false sein

HashSet und eigene Klassen

Bei eigenen Klassen sollten für die Verwendung in einem HashSet equals() und hashCode() passend überschrieben werden.

@Override
public boolean equals(Object o) {
    ...
}

@Override
public int hashCode() {
    ...
}

Map und HashMap

Eine Map speichert Schlüssel-Wert-Paare. Jeder Schlüssel ist eindeutig. Bei einer HashMap werden hashCode() und equals() des Keys verwendet.

Map<String, Integer> alter = new HashMap<>();

alter.put("Anna", 17);
alter.put("Max", 18);

System.out.println(alter.get("Max"));       // 18
System.out.println(alter.containsKey("Anna")); // true

Zusammenhang HashSet und HashMap

Ein HashSet verwendet intern eine HashMap. Die Set-Elemente werden dabei als Keys gespeichert; der zugehörige Wert ist intern nur ein Dummy-Wert.

HashSet:  Element
             ↓
         Key einer internen HashMap

LinkedHashMap

LinkedHashMap verwendet ebenfalls Hashing, führt aber zusätzlich eine verkettete Reihenfolge. Standardmäßig entspricht sie der Einfügereihenfolge.

Sortierte Collections

TreeSet

Ein TreeSet verwendet kein Hashing zur Ordnung. Die Elemente werden über Comparable/compareTo() oder einen Comparator verglichen.

Set<String> namen = new TreeSet<>();
namen.add("Zoe");
namen.add("Anna");
namen.add("Max");

// Iteration: Anna, Max, Zoe

Der Vergleich bestimmt sowohl die Sortierreihenfolge als auch, ob ein Element für das TreeSet bereits vorhanden ist:

compareTo(other) < 0   // dieses Element ist kleiner
compareTo(other) == 0  // beide gelten für das TreeSet als gleich
compareTo(other) > 0   // dieses Element ist größer

Liefert compareTo() bzw. Comparator.compare() den Wert 0, wird das zweite Element nicht eingefügt. Das gilt für das TreeSet auch dann, wenn equals() für die beiden Objekte false liefern würde. Daher sollte die natürliche Ordnung möglichst mit equals() konsistent sein.

Bei eigenen Klassen gibt es zwei Möglichkeiten: Die Klasse implementiert Comparable<T> und definiert damit ihre natürliche Ordnung, oder dem TreeSet wird beim Erzeugen ein Comparator<T> übergeben.

class Person implements Comparable<Person> {
    String name;

    Person(String name) {
        this.name = name;
    }

    @Override
    public int compareTo(Person other) {
        return this.name.compareTo(other.name);
    }
}

Set<Person> personen = new TreeSet<>();

Alternativ kann die Sortierregel von außen vorgegeben werden:

Set<Person> personen = new TreeSet<>(
        Comparator.comparing(p -> p.name)
);

NavigableSet

NavigableSet ist ein Interface für sortierte Mengen mit zusätzlichen Navigationsmethoden. TreeSet implementiert NavigableSet.

NavigableSet<Integer> zahlen = new TreeSet<>();
zahlen.addAll(List.of(10, 20, 30, 40));

zahlen.lower(30);   // 20
zahlen.floor(30);   // 30
zahlen.ceiling(25); // 30
zahlen.higher(30);  // 40

TreeMap

Eine TreeMap speichert Schlüssel-Wert-Paare sortiert nach den Keys. Die Keys benötigen eine natürliche Ordnung oder einen Comparator.

Welche Datenstruktur verwende ich?

Duplikate + Index benötigt?        → ArrayList
Keine Duplikate, schnell suchen?   → HashSet
Keine Duplikate + Einfügereihenfolge? → LinkedHashSet
Keine Duplikate + sortiert?        → TreeSet
Key → Value, schnell suchen?       → HashMap
Key → Value + Einfügereihenfolge?  → LinkedHashMap
Key → Value + nach Key sortiert?   → TreeMap

Übungen

1. List – Einfügen und Entfernen

Erstelle eine ArrayList<String> mit ["apple", "banana", "cherry", "banana"]. Füge "dates" an Index 1 ein und entferne anschließend das Element an Index 2. Gib die Liste vor und nach den Änderungen aus.

Verwende add(index, element) und remove(index).

List<String> list = new ArrayList<>(List.of("apple", "banana", "cherry", "banana"));
System.out.println(list);
list.add(1, "dates");
list.remove(2);
System.out.println(list);

2. remove(Object) vs. remove(int)

Erzeuge List<Integer> nums = new ArrayList<>(List.of(1,2,3,2,4));. Rufe zuerst nums.remove(2) und danach nums.remove(Integer.valueOf(2)) auf. Erkläre den Unterschied.

Bei List existieren zwei überladene remove()-Methoden.

nums.remove(2);                  // int: Index 2 → entfernt 3
nums.remove(Integer.valueOf(2)); // Object: entfernt erstes Vorkommen von 2

Nach dem ersten Aufruf: [1, 2, 2, 4], danach: [1, 2, 4].

3. Arrays.asList – Verbindung zum Array

Erzeuge ein Array und daraus mit Arrays.asList() eine Liste. Ändere anschließend das Array und beobachte die Liste. Versuche danach, ein Element hinzuzufügen.

Die Liste besitzt eine fixe Größe und verwendet das ursprüngliche Array als Speicher.

String[] a = {"x", "y", "z"};
List<String> l = Arrays.asList(a);
a[1] = "Y";
System.out.println(l); // [x, Y, z]
l.add("w");            // UnsupportedOperationException

4. ConcurrentModification vermeiden

Lösche aus einer ArrayList<String> alle Strings mit weniger als 5 Zeichen. Zeige zuerst, warum direktes list.remove() in einer for-each-Schleife problematisch ist, und löse die Aufgabe danach mit einem Iterator.

Der Iterator muss die strukturelle Änderung selbst durchführen.

Falscher Ansatz: Die Liste wird direkt verändert, obwohl gerade über sie iteriert wird.

List<String> list = new ArrayList<>(List.of("short", "looooong", "mini", "medium", "mi"));

// FALSCH:
for (String s : list) {
    if (s.length() < 5) {
        list.remove(s); // direkte Änderung während der Iteration
                        // → kann zu ConcurrentModificationException führen
    }
}

Richtig: Das Entfernen erfolgt über denselben Iterator, der die Liste durchläuft.

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().length() < 5) {
        it.remove();
    }
}
System.out.println(list); // [short, looooong, medium]

5. ListIterator – Einfügen während des Durchlaufens

Füge beim Durchlaufen der Liste ["alpha", "beta", "atom", "gamma"] hinter jedes Element, das mit "a" beginnt, sofort "*" ein. Warum reicht ein normaler Iterator dafür nicht?

ListIterator besitzt zusätzlich die Methode add().

ListIterator<String> li = list.listIterator();
while (li.hasNext()) {
    String s = li.next();
    if (s.startsWith("a")) {
        li.add("*");
    }
}

Das Interface Iterator bietet remove(), aber kein add() oder set().

6. equals()/hashCode() – Contract-Check

Eine Klasse Person vergleicht in equals() die Felder name und town. hashCode() verwendet zunächst nur name. Verletzt das den Contract? Verbessere anschließend die Implementierung.

Gleicher Hashcode verlangt nicht automatisch equals() == true.

Nein. Zwei ungleiche Objekte dürfen denselben Hashcode besitzen. Die Implementierung kann aber unnötig viele Kollisionen erzeugen. Sinnvoll ist:

@Override
public int hashCode() {
    return Objects.hash(name, town);
}

7. Comparable implementieren

Implementiere Comparable<Employee>, sodass Mitarbeiter nach Namen natürlich sortiert werden. Sortiere anschließend eine Liste und erkläre die Bedeutung eines negativen, null bzw. positiven Rückgabewerts von compareTo().

Delegiere den Vergleich an String.compareTo().

class Employee implements Comparable<Employee> {
    String name;

    @Override
    public int compareTo(Employee other) {
        return this.name.compareTo(other.name);
    }
}

list.sort(null); // natürliche Ordnung

< 0: davor, 0: gleich in der Ordnung, > 0: danach.

8. Eigener Comparator

Erstelle einen Comparator<Employee>, der primär nach name und bei gleichem Namen nach yearsEmployed aufsteigend sortiert. Vergleiche die Reihenfolge mit der natürlichen Ordnung.

Verwende Comparator.comparing() und thenComparingInt().

Comparator<Employee> cmp = Comparator
        .comparing((Employee e) -> e.name)
        .thenComparingInt(e -> e.yearsEmployed);

list.sort(cmp);

Die natürliche Ordnung stammt aus compareTo(). Ein Comparator kann unabhängig davon eine andere oder zusätzliche Sortierregel definieren.

9. Hashtable, HashMap und ConcurrentHashMap

Nenne drei Unterschiede zwischen Hashtable und HashMap. Wann ist ConcurrentHashMap vorzuziehen?

Denke an Synchronisation, null und Legacy-Code.

  • HashMap ist nicht synchronisiert; Hashtable synchronisiert seine Methoden.
  • HashMap erlaubt einen null-Key und null-Values; Hashtable erlaubt keine null-Keys oder -Values.
  • Hashtable ist eine Legacy-Klasse; für neuen Code wird normalerweise HashMap verwendet.

Wenn mehrere Threads gemeinsam auf eine Map zugreifen und Thread-Sicherheit erforderlich ist, ist häufig ConcurrentHashMap die passendere moderne Datenstruktur.

10. HashSet vs. TreeSet

Füge "Banane", "Apfel", "Orange" und "Kiwi" sowohl in ein HashSet als auch in ein TreeSet ein. Vergleiche die Ausgabe und erkläre den Unterschied.

Nur eine der beiden Implementierungen garantiert eine Sortierreihenfolge.

Set<String> hashSet = new HashSet<>();
hashSet.addAll(List.of("Banane", "Apfel", "Orange", "Kiwi"));

Set<String> treeSet = new TreeSet<>(hashSet);

System.out.println(hashSet); // Reihenfolge nicht garantiert
System.out.println(treeSet); // [Apfel, Banane, Kiwi, Orange]

Wichtig: Eine konkrete Ausgabereihenfolge des HashSet darf nicht vorausgesetzt werden.

11. Worthäufigkeit mit Map

Analysiere den Text "Dies ist ein Beispieltext. Dies ist ein einfaches Beispiel." und zähle mit einer Map<String,Integer>, wie oft jedes Wort vorkommt.

Normalisiere die Wörter und verwende getOrDefault().

Map<String, Integer> wordCount = new HashMap<>();
String text = "Dies ist ein Beispieltext. Dies ist ein einfaches Beispiel.";

for (String word : text.split(" ")) {
    word = word.toLowerCase().replace(".", "").replace(",", "");
    wordCount.put(word, wordCount.getOrDefault(word, 0) + 1);
}

System.out.println(wordCount);

12. Key/Value-Paare

Speichere 1:"Banane", 2:"Apfel", 3:"Orange" und 4:"Kiwi" in einer Map. Prüfe einen Key, durchlaufe alle Paare, lösche einen Eintrag und gib anschließend alle Keys sowie alle Values aus.

Verwende containsKey(), entrySet(), remove(), keySet() und values().

Map<Integer, String> map = new HashMap<>();
map.put(1, "Banane");
map.put(2, "Apfel");
map.put(3, "Orange");
map.put(4, "Kiwi");

System.out.println(map.containsKey(1));

for (Map.Entry<Integer, String> entry : map.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}

map.remove(3);

for (Integer key : map.keySet()) {
    System.out.println(key);
}

for (String value : map.values()) {
    System.out.println(value);
}
