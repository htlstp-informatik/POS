Java Generics

Typsichere und wiederverwendbare Klassen und Methoden

Was sind Generics?

Mit Generics können Klassen, Interfaces und Methoden so geschrieben werden, dass sie mit unterschiedlichen Datentypen arbeiten können.

Der konkrete Datentyp wird erst bei der Verwendung festgelegt. Dadurch wird der Code wiederverwendbar und gleichzeitig typsicher. 

GenericBox<Integer> box = new GenericBox<>();
box.setValue(3);

int value = box.getValue();

Der Typ Integer wird hier als Typparameter verwendet. Der Compiler stellt sicher, dass nur passende Werte gespeichert werden.

Warum Generics?

Ohne Generics

Vor Java 5 speicherten Collections ihre Elemente als Object. Beim Auslesen war deshalb häufig ein Cast notwendig. 

List list = new ArrayList();

list.add("Alice");

String name = (String) list.get(0);

Wird ein falscher Typ gespeichert oder falsch gecastet, kann erst zur Laufzeit eine ClassCastException auftreten.

Mit Generics

List<String> list = new ArrayList<>();

list.add("Alice");

String name = list.get(0);

Vorteile von Generics:

  • Typsicherheit bereits beim Kompilieren
  • kein Cast beim Auslesen notwendig
  • bessere Lesbarkeit
  • bessere Wiederverwendbarkeit

Generische Klassen

Das Problem ohne Generics

Möchten wir eine Box für verschiedene Datentypen verwenden, müssten wir ohne Generics für jeden Typ eine eigene Klasse schreiben. 

public class IntegerBox {
    private Integer value;

    public void setValue(Integer value) {
        this.value = value;
    }

    public Integer getValue() {
        return value;
    }
}

Für Double wäre dann eine zweite, fast gleiche Klasse notwendig.

Die Idee mit Object

public class ObjectBox {
    private Object value;

    public void setValue(Object value) {
        this.value = value;
    }

    public Object getValue() {
        return value;
    }
}

Damit kann zwar jeder Objekttyp gespeichert werden, aber beim Auslesen muss wieder gecastet werden. Außerdem kann versehentlich ein falscher Typ gespeichert werden.

Die generische Lösung

public class GenericBox<T> {
    private T value;

    public void setValue(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}

T ist ein Typparameter. Er steht zunächst nur als Platzhalter für einen später festgelegten Typ. 

GenericBox<Integer> intBox = new GenericBox<>();

intBox.setValue(3);

int value = intBox.getValue();

In diesem Objekt steht T für Integer. Der Diamond-Operator <> kann verwendet werden, wenn Java den Typ aus der linken Seite ableiten kann. 

// Compilerfehler:
intBox.setValue("TEST");

Mehrere Typparameter

public class Entry<K, V> {
    private K key;
    private V value;

    public Entry(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() {
        return key;
    }

    public V getValue() {
        return value;
    }
}
Entry<Integer, String> entry =
        new Entry<>(1, "Alice");

Häufig verwendete Namen für Typparameter sind zum Beispiel T für Type, K für Key und V für Value.

Generische Methoden

Auch einzelne Methoden können eigene Typparameter besitzen. Die Klasse selbst muss dafür nicht generisch sein.

Der Typparameter steht nach dem Modifier und vor dem Rückgabetyp. 

public static <T> T first(T a, T b) {
    return a;
}
String text = first("A", "B");
Integer zahl = first(3, 4);

Java kann den Typ beim Methodenaufruf meistens automatisch ermitteln. Das nennt man Type Inference. 

PairUtil.<Integer, Integer>createPair(3, 4);

PairUtil.createPair(3, 4);

Generics und Vererbung

Bei normalen Typen gilt: 

Integer x = 4;
Number y = x;
Object o = x;

Bei generischen Typen gilt das aber nicht automatisch: 

GenericBox<Integer> integerBox = new GenericBox<>();
GenericBox<Number> numberBox = new GenericBox<>();

// Compilerfehler:
numberBox = integerBox;

GenericBox<Number> ist also keine Oberklasse von GenericBox<Integer>.

Das verhindert, dass über eine GenericBox<Number> beispielsweise ein Double in eine eigentlich als GenericBox<Integer> gedachte Box geschrieben wird.

Bounded Types

Ein Typparameter kann auf bestimmte Typen eingeschränkt werden. 

public class NumberBox<T extends Number> {
    private T content;

    public NumberBox(T content) {
        this.content = content;
    }

    public int intValue() {
        return content.intValue();
    }
}

T extends Number bedeutet: Als Typ sind Number und Unterklassen von Number erlaubt. 

new NumberBox<>(3);
new NumberBox<>(3.1415);

// Compilerfehler:
new NumberBox<>("Text");

Wildcards

Unbounded Wildcard: <?>

? bedeutet, dass der konkrete Typ nicht bekannt sein muss. 

void printBox(GenericBox<?> box) {
    System.out.println(box.getValue());
}

Der Wert kann als Object gelesen werden. Ein konkreter Wert kann aber nicht sicher hineingeschrieben werden.

Upper Bounded Wildcard: <? extends T>

GenericBox<? extends Number> box;

Die Box darf eine GenericBox<Number>, GenericBox<Integer>, GenericBox<Double> usw. referenzieren.

Sicher gelesen werden kann eine Number. 

Number value = box.getValue();

Schreiben ist dagegen nicht möglich, weil der tatsächliche konkrete Zahlentyp unbekannt ist. 

// nicht erlaubt:
box.setValue(3);
box.setValue(3.14);

Lower Bounded Wildcard: <? super T>

GenericBox<? super Integer> box;

Möglich sind zum Beispiel GenericBox<Integer>, GenericBox<Number> oder GenericBox<Object>.

Ein Integer kann sicher hineingeschrieben werden. Beim Lesen ist dagegen nur Object garantiert. 

box.setValue(42);

Object value = box.getValue();

PECS

Als Merkhilfe gilt: Producer Extends, Consumer Super.

  • ? extends T: gut zum Lesen
  • ? super T: gut zum Schreiben

Einschränkungen von Generics

Keine primitiven Datentypen

// nicht erlaubt:
GenericBox<int> box;

// stattdessen:
GenericBox<Integer> box;

Keine Instanz von T erzeugen

// nicht erlaubt:
T value = new T();

Keine Arrays mit konkretem generischem Typ erzeugen

// nicht erlaubt:
GenericBox<String>[] boxes =
        new GenericBox<String>[10];

Kein static Feld mit dem Typparameter der Klasse

public class GenericBox<T> {

    // nicht erlaubt:
    static T value;
}

Raw Types vermeiden

// Raw Type - vermeiden:
GenericBox box = new GenericBox();

// besser:
GenericBox<Integer> box = new GenericBox<>();

Raw Types existieren hauptsächlich aus Gründen der Rückwärtskompatibilität. Dabei geht die Typsicherheit verloren.

Type Erasure

Die Typinformationen von Generics werden beim Übersetzen weitgehend entfernt. Zur Laufzeit existieren deshalb beispielsweise List<Integer> und List<Float> als dieselbe Laufzeitklasse. 

List<Integer> li = new ArrayList<>();
List<Float> lf = new ArrayList<>();

System.out.println(li.getClass() == lf.getClass());
// true

Übungen

Übung 1: GenericBox

Erstelle eine generische Klasse Box<T>. Eine Box soll genau einen Wert speichern können.

Implementiere:

  • ein Attribut value
  • einen Konstruktor
  • getValue()
  • setValue(...)

Erzeuge anschließend eine Box<String> und eine Box<Integer>. 

public class Box<T> {
    private T value;

    ...
}
public class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }
}
Box<String> textBox = new Box<>("Hallo");
Box<Integer> numberBox = new Box<>(42);

System.out.println(textBox.getValue());
System.out.println(numberBox.getValue());

Übung 2: Pair mit zwei Typparametern

Erstelle eine generische Klasse Pair<A, B>, die zwei Werte unterschiedlicher Typen speichern kann.

Erzeuge anschließend: 

Pair<String, Integer> person =
        new Pair<>("Anna", 17);

Die Klasse benötigt zwei Typparameter und zwei Attribute. 

public class Pair<A, B> {
    private A first;
    private B second;

    public Pair(A first, B second) {
        this.first = first;
        this.second = second;
    }

    public A getFirst() {
        return first;
    }

    public B getSecond() {
        return second;
    }
}

Übung 3: Generische Methode

Schreibe eine generische Methode printArray(...), die alle Elemente eines Arrays ausgibt. Die Methode soll mit unterschiedlichen Objekttypen funktionieren.

Der Typparameter steht vor dem Rückgabetyp: 

public static <T> void printArray(T[] array) {
    ...
}
public static <T> void printArray(T[] array) {
    for (T element : array) {
        System.out.println(element);
    }
}
String[] namen = {"Anna", "Max"};
Integer[] zahlen = {1, 2, 3};

printArray(namen);
printArray(zahlen);

Übung 4: Zahlen addieren

Gegeben ist die Klasse GenericBox<T>. Schreibe eine Methode, die die Werte aus zwei Boxen addiert. Die Boxen sollen unterschiedliche Zahlentypen enthalten dürfen.

Zum Beispiel soll Folgendes möglich sein: 

GenericBox<Integer> box1 = new GenericBox<>();
box1.setValue(5);

GenericBox<Double> box2 = new GenericBox<>();
box2.setValue(3.5);

System.out.println(calculateSum(box1, box2));

Verwende eine Upper Bounded Wildcard: ? extends Number. 

public static double calculateSum(
        GenericBox<? extends Number> box1,
        GenericBox<? extends Number> box2) {

    return box1.getValue().doubleValue()
            + box2.getValue().doubleValue();
}

Übung 5: Type Erasure

Schreibe ein Programm, das prüft, ob eine ArrayList<Integer> und eine ArrayList<String> zur Laufzeit denselben Typ haben. Erkläre das Ergebnis.

Vergleiche die Ergebnisse von getClass(). 

import java.util.ArrayList;
import java.util.List;

public class TypeErasureDemo {

    public static void main(String[] args) {
        List<Integer> integerList = new ArrayList<>();
        List<String> stringList = new ArrayList<>();

        System.out.println(
                integerList.getClass() == stringList.getClass()
        );
    }
}

Die Ausgabe ist true. Durch Type Erasure sind die konkreten Typparameter Integer und String zur Laufzeit nicht mehr als unterschiedliche Klassen vorhanden.

Übung 6: Raw Types und ClassCastException

Zeige anhand eines Beispiels, wie die Verwendung eines Raw Types bei GenericBox zu einer ClassCastException führen kann.

Weise zuerst eine GenericBox<String> einer Raw-Type-Referenz zu und speichere danach einen Integer hinein. 

GenericBox<String> stringBox = new GenericBox<>();

GenericBox rawBox = stringBox;
rawBox.setValue(42);

String text = stringBox.getValue();
// ClassCastException

Durch den Raw Type geht die Typsicherheit verloren. Der Compiler kann nicht mehr verhindern, dass ein falscher Typ in die Box geschrieben wird.

Übung 7: Einschränkungen von Generics

Erkläre anhand der folgenden Beispiele, warum sie nicht erlaubt sind. 

// a)
T value = new T();

// b)
GenericBox<String>[] boxes =
        new GenericBox<String>[10];

Denke bei a) an Type Erasure und bei b) an die Kombination aus Arrays und generischen Typen.

a) new T() ist nicht erlaubt, weil der konkrete Typ von T zur Laufzeit nicht bekannt ist.

b) Ein Array wie new GenericBox<String>[10] darf nicht erzeugt werden. Arrays kennen ihren Komponententyp zur Laufzeit, bei Generics wird die Typinformation dagegen durch Type Erasure entfernt.

Übung 8: NumberBox mit Bounded Type

Erstelle eine Klasse NumberBox<T extends Number> mit einer Methode int intValue(). Teste die Klasse mit Integer und Double.

Weil T von Number abgeleitet sein muss, kannst du intValue() direkt auf dem gespeicherten Wert aufrufen. 

public class NumberBox<T extends Number> {
    private T value;

    public NumberBox(T value) {
        this.value = value;
    }

    public int intValue() {
        return value.intValue();
    }
}
NumberBox<Integer> intBox =
        new NumberBox<>(42);

NumberBox<Double> doubleBox =
        new NumberBox<>(3.14);

System.out.println(intBox.intValue());
System.out.println(doubleBox.intValue());

Übung 9: Lower Bounded Wildcard

Implementiere eine Methode, die eine GenericBox<? super Integer> entgegennimmt und dort eine Zahl speichert.

Prüfe anschließend, welchen Typ du mit getValue() ohne Cast sicher auslesen kannst.

Ein Integer darf sicher geschrieben werden. Beim Lesen ist nur Object garantiert. 

public static void storeInteger(
        GenericBox<? super Integer> box) {

    box.setValue(42);

    Object value = box.getValue();
    System.out.println(value);
}

Eine direkte Zuweisung an Integer ist nicht sicher: 

// nicht erlaubt:
Integer value = box.getValue();

Die Box könnte nämlich auch eine GenericBox<Number> oder GenericBox<Object> sein.

Übung 10: Unbounded Wildcard

Implementiere eine Methode, die die Größe einer beliebigen Liste zurückgibt. Verwende dafür List<?>.

Für size() musst du den konkreten Elementtyp der Liste nicht kennen. 

public static int getSize(List<?> list) {
    return list.size();
}
List<String> namen = List.of("Anna", "Max");
List<Integer> zahlen = List.of(1, 2, 3);

System.out.println(getSize(namen));
System.out.println(getSize(zahlen));

Zusatzaufgabe 11: Comparable und Generics

Untersuche die folgende Methode: 

public static <T extends Comparable<? super T>>
T test(List<T> list) {
    ...
}

Erkläre, was die Einschränkung T extends Comparable<? super T> bedeutet und zeige ein Beispiel mit einem passenden Datentyp.

Die Methode verlangt einen Typ T, dessen Objekte miteinander verglichen werden können.

T extends Comparable<? super T> bedeutet: T muss mit sich selbst oder mit einem Obertyp von T vergleichbar sein.

Dadurch kann die Methode innerhalb der Liste Werte mit compareTo(...) vergleichen. 

public static <T extends Comparable<? super T>>
T test(List<T> list) {
    T max = list.get(0);

    for (T value : list) {
        if (value.compareTo(max) > 0) {
            max = value;
        }
    }

    return max;
}
List<Integer> zahlen = List.of(4, 9, 2, 7);

System.out.println(test(zahlen));
// 9
