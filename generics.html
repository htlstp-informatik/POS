Java Generics

Typsichere und wiederverwendbare Klassen und Methoden

Start Warum Generics? Klassen Methoden Vererbung Bounded Types Wildcards Einschränkungen Übungen

Was sind Generics?

Mit Generics können Klassen, Interfaces und Methoden so geschrieben werden, dass sie mit unterschiedlichen Datentypen arbeiten können. Der konkrete Datentyp wird erst bei der Verwendung festgelegt. 

GenericBox<Integer> box = new GenericBox<>();
box.setValue(3);
int value = box.getValue();

Dadurch wird der Code wiederverwendbar und gleichzeitig typsicher.

Warum Generics?

Ohne Generics

Vor Java 5 speicherten Collections ihre Elemente als Object. Beim Auslesen war deshalb ein Cast notwendig. 

List list = new ArrayList();
list.add("Alice");
String name = (String) list.get(0);

Ein falscher Typ kann dadurch erst zur Laufzeit zu einer ClassCastException führen.

Mit Generics

List<String> list = new ArrayList<>();
list.add("Alice");
String name = list.get(0);
  • Typsicherheit zur Compile-Zeit
  • kein Cast beim Auslesen notwendig
  • bessere Lesbarkeit
  • bessere Wiederverwendbarkeit

Generische Klassen

Das Problem ohne Generics

Ohne Generics müsste für verschiedene Datentypen jeweils eine eigene Box geschrieben werden, zum Beispiel eine IntegerBox und eine DoubleBox. 

public class IntegerBox {
    private Integer value;

    public void setValue(Integer value) {
        this.value = value;
    }

    public Integer getValue() {
        return value;
    }
}

Die Idee mit Object

public class ObjectBox {
    private Object value;

    public void setValue(Object value) {
        this.value = value;
    }

    public Object getValue() {
        return value;
    }
}

Damit kann zwar jeder Objekttyp gespeichert werden, aber beim Auslesen ist ein Cast notwendig und die Typsicherheit geht verloren.

Die generische Lösung

public class GenericBox<T> {
    private T value;

    public void setValue(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}

T ist ein Typparameter. Er ist ein Platzhalter für den später verwendeten Typ. 

GenericBox<Integer> intBox = new GenericBox<>();
intBox.setValue(3);
int value = intBox.getValue();

// Compilerfehler:
// intBox.setValue("TEST");

Der Diamond-Operator <> kann verwendet werden, wenn Java den Typ aus dem Zusammenhang ableiten kann.

Mehrere Typparameter

public class Entry<K, V> {
    private K key;
    private V value;

    public Entry(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() {
        return key;
    }

    public V getValue() {
        return value;
    }
}
Entry<Integer, String> entry = new Entry<>(1, "Alice");

Häufig verwendete Bezeichnungen sind T für Type, K für Key und V für Value.

Generische Methoden

Auch einzelne Methoden können eigene Typparameter besitzen. Der Typparameter steht nach dem Modifier und vor dem Rückgabetyp. 

public static <S, T> Pair<S, T> createPair(S first, T second) {
    return new Pair<>(first, second);
}

Java kann die Typen beim Aufruf meistens automatisch bestimmen. Das nennt man Type Inference. 

PairUtil.<Integer, Integer>createPair(3, 4);
PairUtil.createPair(3, 4);

Generics und Vererbung

Bei normalen Typen gilt:

Integer x = 4;
Number y = x;
Object o = x;

Bei generischen Typen gilt das nicht automatisch:

GenericBox<Integer> integerBox = new GenericBox<>();
GenericBox<Number> numberBox = new GenericBox<>();

// Compilerfehler:
// numberBox = integerBox;

GenericBox<Number> ist keine Oberklasse von GenericBox<Integer>.

Bounded Types

Ein Typparameter kann auf bestimmte Typen eingeschränkt werden. 

public class NumberBox<T extends Number> {
    private T content;

    public NumberBox(T content) {
        this.content = content;
    }

    public int intValue() {
        return content.intValue();
    }
}

T extends Number bedeutet: Erlaubt sind Number und Unterklassen von Number. 

new NumberBox<>(3);
new NumberBox<>(3.1415);

// Compilerfehler:
// new NumberBox<>("Text");

Wildcards

Unbounded Wildcard: <?>

Bei ? ist der konkrete Typ unbekannt. 

void printBox(GenericBox<?> box) {
    System.out.println(box.getValue());
}

Sicher gelesen werden kann nur als Object. Ein konkreter Wert kann nicht sicher hineingeschrieben werden.

Upper Bounded Wildcard: <? extends T>

GenericBox<? extends Number> box;

Die Box kann zum Beispiel eine GenericBox<Integer>, GenericBox<Double> oder GenericBox<Number> referenzieren.

Lesen ist sicher, weil der Wert mindestens ein Number ist. Schreiben ist nicht sicher, weil der konkrete Untertyp unbekannt ist. 

Number value = box.getValue();

// nicht erlaubt:
// box.setValue(3);
// box.setValue(3.14);

Lower Bounded Wildcard: <? super T>

GenericBox<? super Integer> box;

Möglich sind zum Beispiel GenericBox<Integer>, GenericBox<Number> und GenericBox<Object>.

Ein Integer kann sicher hineingeschrieben werden. Beim Lesen ist nur Object garantiert. 

box.setValue(42);
Object value = box.getValue();

PECS

Merkhilfe: Producer Extends, Consumer Super.

  • ? extends T: Lesen ist sicher
  • ? super T: Schreiben ist sicher

Einschränkungen und Besonderheiten

Keine primitiven Datentypen

// nicht erlaubt:
// GenericBox<int> box;

GenericBox<Integer> box;

Keine Instanz von T erzeugen

// nicht erlaubt:
// T value = new T();

Keine Arrays mit konkretem generischem Typ erzeugen

// nicht erlaubt:
// GenericBox<String>[] boxes = new GenericBox<String>[10];

Raw Types vermeiden

GenericBox rawBox = new GenericBox();

Bei Raw Types fehlt die Typinformation. Sie existieren hauptsächlich aus Gründen der Rückwärtskompatibilität und sollten vermieden werden.

Type Erasure

Die konkreten Typparameter werden beim Übersetzen weitgehend entfernt. Deshalb besitzen zum Beispiel ArrayList<Integer> und ArrayList<String> zur Laufzeit dieselbe Klasse.

Übungen

1. Motivation

Erkläre anhand eines Beispiels, warum Generics in Java eingeführt wurden.

Vergleiche eine Collection ohne Generics mit einer List<String>. Achte besonders auf Casts und Typsicherheit. 

List list = new ArrayList();
list.add("Alice");
String name = (String) list.get(0);

Ohne Generics ist beim Auslesen ein Cast notwendig. Außerdem kann versehentlich ein falscher Typ gespeichert werden. 

List<String> list = new ArrayList<>();
list.add("Alice");
String name = list.get(0);

Mit Generics prüft der Compiler den Typ bereits beim Übersetzen. Ein Cast beim Auslesen ist nicht notwendig.

2. Generische Klasse

Implementiere eine generische Klasse GenericBox<T> mit den Methoden setValue() und getValue(). Zeige, wie man eine Box für Integer und eine Box für String verwendet. 

public class GenericBox<T> {
    private T value;
}
public class GenericBox<T> {
    private T value;

    public void setValue(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}
GenericBox<Integer> intBox = new GenericBox<>();
intBox.setValue(42);

GenericBox<String> stringBox = new GenericBox<>();
stringBox.setValue("Hallo");

3. Generische Methode

Schreibe eine generische Methode createPair, die zwei Objekte entgegennimmt und ein Pair<S, T> zurückgibt.

Die Typparameter der Methode stehen vor dem Rückgabetyp. 

public static <S, T> Pair<S, T> createPair(S first, T second) {
    ...
}
public static <S, T> Pair<S, T> createPair(S first, T second) {
    return new Pair<>(first, second);
}
Pair<String, Integer> pair = createPair("Anna", 17);

4. Type Erasure

Schreibe ein Programm, das prüft, ob new ArrayList<Integer>() und new ArrayList<String>() zur Laufzeit denselben Typ haben.

Vergleiche die Ergebnisse mit getClass(). 

ArrayList<Integer> a = new ArrayList<>();
ArrayList<String> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());

Die Ausgabe ist true. Durch Type Erasure sind die konkreten Typparameter zur Laufzeit nicht mehr vorhanden.

5. Raw Types

Zeige anhand eines einfachen Beispiels, wie die Verwendung eines Raw Types bei GenericBox zu einer ClassCastException führen kann.

Erzeuge zuerst eine GenericBox<String> und weise dieselbe Box anschließend einer Raw-Type-Referenz zu. 

GenericBox<String> stringBox = new GenericBox<>();
GenericBox rawBox = stringBox;
rawBox.setValue(42);
String text = stringBox.getValue(); // ClassCastException

Über den Raw Type geht die Typprüfung verloren. Deshalb kann ein Integer in die eigentlich als GenericBox<String> verwendete Box geschrieben werden. Beim Auslesen als String entsteht die ClassCastException.

6. Einschränkungen

a) Warum ist new T() in einer generischen Klasse nicht erlaubt?

b) Was passiert, wenn du GenericBox<String>[] erzeugen möchtest?

Denke daran, dass der konkrete Typ von T zur Laufzeit durch Type Erasure nicht mehr bekannt ist.

a) new T() ist nicht erlaubt, weil der Compiler nicht weiß, welcher konkrete Konstruktor für T aufgerufen werden soll. Durch Type Erasure steht der konkrete Typparameter außerdem zur Laufzeit nicht zur Verfügung. 

// Compilerfehler:
// T value = new T();

b) Auch ein Array mit einem konkreten generischen Typ kann nicht direkt erzeugt werden. 

// Compilerfehler:
// GenericBox<String>[] boxes = new GenericBox<String>[10];

7. Bounded Types

Erstelle eine Klasse NumberBox<T extends Number> mit einer Methode int intValue(). Teste sie mit Integer und Double.

Weil T mindestens ein Number ist, darfst du Methoden von Number direkt verwenden. 

public class NumberBox<T extends Number> {
    private T value;

    public NumberBox(T value) {
        this.value = value;
    }

    public int intValue() {
        return value.intValue();
    }
}
NumberBox<Integer> intBox = new NumberBox<>(42);
NumberBox<Double> doubleBox = new NumberBox<>(3.14);
System.out.println(intBox.intValue());
System.out.println(doubleBox.intValue());

8. Upper Bounded Wildcards

Implementiere eine Methode calculateSum, die zwei GenericBox<? extends Number> entgegennimmt und deren Werte addiert. Kannst du in der Methode selbst mit setValue() die übergebenen Werte überschreiben?

Bei ? extends Number ist der konkrete Untertyp unbekannt. Lesen ist sicher, Schreiben eines konkreten Wertes nicht.

Bei ? extends Number weiß der Compiler nicht, weiß der Compiler nicht, welcher konkrete Untertyp von Number in der jeweiligen Box verwendet wird. Eine Box könnte zum Beispiel Integer, die andere Double enthalten. Deshalb darf kein konkreter Wert hineingeschrieben werden (außer null).

Deshalb darf kein konkreter Wert mit setValue() hineingeschrieben werden (außer null). Herauslesen ist dagegen sicher: Der Wert ist mindestens ein Number. Daher stehen Methoden wie doubleValue() zur Verfügung. 

public static double calculateSum(GenericBox<? extends Number> b1, GenericBox<? extends Number> b2) {
    // b1.setValue(44); // nicht erlaubt: der konkrete Untertyp von Number ist unbekannt
    return b1.getValue().doubleValue() + b2.getValue().doubleValue();
}

9. Lower Bounded Wildcards

Implementiere eine Methode, die eine GenericBox<? super Integer> entgegennimmt und dort eine Zahl speichert. Lies anschließend mit getValue() einen Wert aus.

Was ist dabei sicher möglich: Schreiben oder Lesen?

Bei ? super Integer ist das Schreiben eines Integer sicher. Beim Lesen ist nur Object garantiert. 

public static void storeInteger(GenericBox<? super Integer> box) {
    box.setValue(42);
    Object value = box.getValue();
    System.out.println(value);
}

Schreiben ist sicher: Ein Integer passt in GenericBox<Integer>, GenericBox<Number> und GenericBox<Object>.

Lesen ist nur als Object sicher: 

Object value = box.getValue();

// nicht erlaubt:
// Integer value = box.getValue();

10. Unbounded Wildcards

Implementiere eine Methode, die die Größe einer List<?> zurückgibt.

Für size() muss der konkrete Elementtyp der Liste nicht bekannt sein. 

public static int getSize(List<?> list) {
    return list.size();
}

Bei List<?> ist der konkrete Typ der Elemente unbekannt. list.get(0) kann daher nur sicher als Object verwendet werden. Der tatsächliche Wert kann natürlich zum Beispiel trotzdem ein String sein.

Mit list.add(...) darf kein konkreter Wert hinzugefügt werden (außer null), weil der tatsächliche Elementtyp unbekannt ist. Methoden, die nicht vom Elementtyp abhängen, wie size(), isEmpty() oder clear(), können dagegen verwendet werden.

11. Comparable und Generics

Schreibe eine Methode test(), die aus einer Liste das größte Element ermittelt und zurückgibt. Die Elemente der Liste müssen miteinander vergleichbar sein. Erkläre anhand des Beispiels, warum ? super T sinnvoll sein kann. 

public static <T extends Comparable<? super T>> T test(List<T> list)

Vergleiche zuerst die strengere Variante <T extends Comparable<T>> mit <T extends Comparable<? super T>>. 

class Person implements Comparable<Person> {
    String name;

    Person(String name) {
        this.name = name;
    }

    @Override
    public int compareTo(Person other) {
        return this.name.compareTo(other.name);
    }
}

class Student extends Person {
    Student(String name) {
        super(name);
    }
}

Zuerst die strengere Variante ohne ? super T: 

public static <T extends Comparable<T>> T test(List<T> list) {
    T max = list.get(0);

    for (T elem : list) {
        if (elem.compareTo(max) > 0) {
            max = elem;
        }
    }

    return max;
}
List<Student> studenten = List.of(new Student("Zoe"), new Student("Mike"));

// Compilerfehler:
// Student max = test(studenten);

Der Fehler entsteht, weil Student durch die Vererbung Comparable<Person> ist und nicht Comparable<Student>.

Mit ? super T wird die Methode allgemeiner: 

public static <T extends Comparable<? super T>> T test(List<T> list) {
    T max = list.get(0);

    for (T elem : list) {
        if (elem.compareTo(max) > 0) {
            max = elem;
        }
    }

    return max;
}
List<Student> studenten = List.of(new Student("Zoe"), new Student("Mike"));
Student max = test(studenten);
System.out.println(max.name);

Für T = Student verlangt Comparable<? super Student>, dass Student mit Student oder einem Obertyp von Student vergleichbar ist. Person ist ein Obertyp von Student - daher ist Comparable<Person> erlaubt. 

Student s = new Student("Anna");
Person p = new Person("Bernd");
int result = s.compareTo(p);

Ein Student kann in diesem Beispiel also nicht nur mit einem Student, sondern auch mit einer Person verglichen werden.

Bei Klassen wie Integer oder Double, die sich selbst vergleichen, wäre auch die strengere Variante Comparable<T> ausreichend. Die Variante mit ? super T ist aber allgemeiner.
