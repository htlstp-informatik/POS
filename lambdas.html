Was ist ein Lambda?

Ein Lambda-Ausdruck beschreibt kurz die Implementierung einer Methode eines funktionalen Interfaces. Damit kannst du beispielsweise eine Sortierregel oder eine Bedingung direkt an eine Methode übergeben.

names.sort((a, b) -> a.compareTo(b));

Du kennst bereits Interfaces, Generics und Comparator mit eigener Klasse. Hier lernst du schrittweise, wie daraus ein Lambda wird. Die Beispiele verwenden Java 11 oder neuer; Lambda-Ausdrücke selbst gibt es seit Java 8.

Von der eigenen Klasse zum Lambda

Alle drei Varianten sortieren dieselbe Liste alphabetisch. Die eigene Klasse kennst du von Collections. Die folgenden Ausschnitte sind alternative Varianten; verwende jeweils eine davon.

1. Eigene Klasse

Die Klasse implementiert das Interface und überschreibt dessen Vergleichsmethode.

class NameComparator implements Comparator<String> {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
}

// Innerhalb von main:
names.sort(new NameComparator());

2. Anonyme Klasse

Die Klasse wird direkt beim Erzeugen des Objekts definiert und erhält keinen eigenen Namen.

names.sort(new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
});

3. Lambda-Ausdruck

Die Parameter und der Methodenrumpf bleiben übrig. Der Compiler kennt die passende Methode aus dem erwarteten Interface Comparator<String>.

names.sort((a, b) -> a.compareTo(b));

Für die Ausschnitte benötigst du java.util.Comparator, java.util.List und java.util.ArrayList.

List<String> names = new ArrayList<>(List.of("Zoe", "Anna", "Ben"));

Syntax verstehen

Parameter → Verarbeitung

Links von -> stehen die Parameter, rechts steht die Verarbeitung.

Comparator<String> cmp = (String a, String b) -> a.compareTo(b);
int result = cmp.compare("Anna", "Ben"); // negativ
TeilBedeutung
(String a, String b)Parameter der Methode compare
->Trennt Parameter und Rumpf
a.compareTo(b)Ergebnis des Ausdrucks wird zurückgegeben

Typen und Klammern

Bei genau einem Parameter ohne ausgeschriebenen Typ dürfen die Klammern entfallen. Bei keinem oder mehreren Parametern sind sie erforderlich.

Predicate<String> empty = text -> text.isEmpty();
Predicate<String> empty2 = (String text) -> text.isEmpty();
Runnable greeting = () -> System.out.println("Hallo!");
Comparator<Integer> numbers = (a, b) -> Integer.compare(a, b);

Ausdruck oder Block

Ein einzelner Ausdruck benötigt kein return. Bei einem Block mit Rückgabewert ist return notwendig.

Function<String, Integer> length = text -> text.length();
Function<String, Integer> length2 = text -> {
    int result = text.length();
    return result;
};
Consumer<String> print = text -> {
    System.out.println("Name: " + text);
};

Funktionale Interfaces

Ein funktionales Interface hat genau eine abstrakte Methode. Zusätzliche default- und static-Methoden sind erlaubt. @FunctionalInterface ist optional und lässt den Compiler die Eignung prüfen.

@FunctionalInterface
interface IntOperation {
    int apply(int a, int b);
}

IntOperation add = (a, b) -> a + b;
IntOperation multiply = (a, b) -> a * b;
System.out.println(add.apply(3, 4));      // 7
System.out.println(multiply.apply(3, 4)); // 12

Der Zieltyp legt Parameter und Rückgabewert fest. Deshalb funktioniert var add = (a, b) -> a + b; nicht.

Verhalten als Argument

static int calculate(int a, int b, IntOperation operation) {
    return operation.apply(a, b);
}

System.out.println(calculate(5, 2, (a, b) -> a + b)); // 7
System.out.println(calculate(5, 2, (a, b) -> a - b)); // 3

Häufige Standard-Interfaces

Die ersten vier Interfaces findest du in java.util.function; Comparator liegt in java.util.

System.out.println(longName.test("Anna")); // false

System.out.println(length.apply("Anna")); // 4
System.out.println(greeting.get());       // Hallo

Lambdas mit Listen

forEach: Elemente verarbeiten

forEach erwartet einen Consumer.

names.forEach(name -> System.out.println(name));

removeIf: Elemente entfernen

removeIf erwartet ein Predicate.

List<String> names = new ArrayList<>(List.of("Anna", "Ben", "Alex"));
names.removeIf(name -> name.startsWith("A"));
System.out.println(names); // [Ben]

replaceAll: Elemente ersetzen

names.replaceAll(name -> name.toUpperCase(java.util.Locale.ROOT));

sort, removeIf und replaceAll verändern die Liste. List.of() allein erzeugt eine unveränderbare Liste.

Employee sortieren

Dieses vollständige Beispiel verbindet die natürliche Ordnung aus Collections mit einem Lambda-Comparator. Speichere es als LambdaDemo.java. Bei gleichem Namen sortiert der Comparator zusätzlich nach Dienstjahren.

import java.util.ArrayList;
import java.util.List;

class Employee implements Comparable<Employee> {
    String name;
    int yearsEmployed;

    Employee(String name, int yearsEmployed) {
        this.name = name;
        this.yearsEmployed = yearsEmployed;
    }

    @Override
    public int compareTo(Employee other) {
        return name.compareTo(other.name);
    }

    @Override
    public String toString() {
        return name + " (" + yearsEmployed + ")";
    }
}

public class LambdaDemo {
    public static void main(String[] args) {
        List<Employee> employees = new ArrayList<>(List.of(
                new Employee("Ben", 3),
                new Employee("Anna", 7),
                new Employee("Anna", 2)));

        employees.sort(null);
        System.out.println(employees); // [Anna (7), Anna (2), Ben (3)]

        employees.sort((e1, e2) -> {
            int result = e1.name.compareTo(e2.name);
            if (result == 0) {
                return Integer.compare(e1.yearsEmployed, e2.yearsEmployed);
            }
            return result;
        });
        System.out.println(employees); // [Anna (2), Anna (7), Ben (3)]
    }
}

List.sort ist stabil: Bei gleichem Vergleichswert bleibt die bisherige Reihenfolge erhalten. Deshalb stehen bei der natürlichen Ordnung Anna (7) und Anna (2) weiterhin in ihrer ursprünglichen Reihenfolge.

Als nächster Schritt: Comparator.comparing()

Im vorherigen Beispiel hast du mit dem Lambda (e1, e2) -> ... die Methode compare des Interfaces Comparator<Employee> selbst implementiert. Du musstest also zwei Employees direkt vergleichen und den zweiten Vergleich mit if selbst programmieren.

Comparator<Employee> cmp = (e1, e2) -> {
    int result = e1.name.compareTo(e2.name);
    if (result == 0) {
        return Integer.compare(e1.yearsEmployed, e2.yearsEmployed);
    }
    return result;
};

Es geht aber auch einfacher: Die statische Methode Comparator.comparing() erzeugt einen Comparator für dich. Du gibst nur an, welches Attribut als Sortierschlüssel dienen soll.

Schritt 1: Ein Lambda zum Auslesen des Namens

Function<Employee, String> getName = (Employee e) -> e.name;

System.out.println(getName.apply(new Employee("Anna", 7))); // Anna

Dieses Lambda implementiert Function<Employee, String> mit der Methode apply(Employee e). Es nimmt einen Employee entgegen und liefert einen String zurück. Es vergleicht noch nichts.

Schritt 2: Aus der Function einen Comparator erzeugen

Comparator<Employee> byName =
        Comparator.comparing((Employee e) -> e.name);

employees.sort(byName);

comparing() verwendet die übergebene Funktion für beide Employees, liest jeweils den Namen aus und vergleicht anschließend die beiden Strings. Das entspricht sinngemäß:

Comparator<Employee> byName =
        (e1, e2) -> e1.name.compareTo(e2.name);

Der ausgeschriebene Parametertyp Employee hilft dem Compiler hier bei der Typableitung.

Schritt 3: Zweiten Sortierschlüssel ergänzen

Comparator<Employee> cmp = Comparator
        .comparing((Employee e) -> e.name)
        .thenComparingInt(e -> e.yearsEmployed);

employees.sort(cmp);
System.out.println(employees); // [Anna (2), Anna (7), Ben (3)]

thenComparingInt wird nur dann für die Sortierreihenfolge entscheidend, wenn zwei Namen gleich sind. Es liest die Dienstjahre aus und vergleicht sie als int. Die gesamte Sortierregel ist damit dieselbe wie beim vorherigen Lambda-Comparator – nur ohne selbst geschriebenes if.

Bisher: Vergleich selbst programmieren Neu: Sortierschlüssel angeben
(e1, e2) -> ... e -> e.name
Zwei Employee-Parameter Ein Employee-Parameter
Lambda implementiert Comparator.compare() Lambda implementiert Function.apply()
Lambda liefert einen Vergleichswert Lambda liefert einen Sortierschlüssel
Zweiten Vergleich selbst mit if behandeln thenComparingInt() ergänzt die zweite Regel

Merke: Comparator.comparing() erhält eine Funktion zum Auslesen eines Sortierschlüssels und baut daraus einen Comparator. Das Lambda e -> e.name ist selbst kein Comparator.

Für diesen Zusatzabschnitt benötigst du außerdem import java.util.Comparator; und für die ausdrücklich deklarierte Function import java.util.function.Function;. Die Beispiele der Schritte 1–3 sind alternative Ausschnitte, die du innerhalb von main verwenden kannst.

Lokale Variablen verwenden

Ein Lambda darf lokale Variablen aus seiner Umgebung lesen, wenn diese final oder effektiv final sind: Ihr Wert wird nach der Initialisierung nicht erneut zugewiesen.

int minLength = 4;
Predicate<String> longEnough = name -> name.length() >= minLength;
System.out.println(longEnough.test("Anna")); // true

Würde zusätzlich minLength++; stehen, wäre die übernommene Variable nicht effektiv final. Bei Referenzen darf sich das referenzierte Objekt dennoch verändern.

Ausblick: Methodenreferenzen

Wenn ein Lambda nur eine vorhandene Methode passend weiterleitet, kann oft eine Methodenreferenz mit :: verwendet werden.

Consumer<String> print = text -> System.out.println(text);
Consumer<String> print2 = System.out::println;

Function<String, Integer> length = text -> text.length();
Function<String, Integer> length2 = String::length;

Comparator<Integer> cmp = (a, b) -> Integer.compare(a, b);
Comparator<Integer> cmp2 = Integer::compare;

Bei System.out::println wird eine Methode eines vorhandenen Objekts verwendet; bei String::length die Methode des übergebenen Strings; bei Integer::compare eine statische Methode.

Übungen

Nutze bei Bedarf die Beispiele aus dem Theorieabschnitt. Für Standard-Interfaces importiere die benötigten Typen aus java.util.function, für Listen und Comparator aus java.util. Ausschnitte mit Aufrufen gehören in main.

1. Lambda lesen

Erkläre die Teile von (a, b) -> Integer.compare(a, b). Welches Interface passt dazu?

Überlege, wie viele Parameter vorhanden sind und welcher Typ zurückgegeben wird.

Das Lambda hat zwei Parameter und liefert einen int-Vergleichswert. Als Zieltyp passt Comparator<Integer>; implementiert wird compare.

Comparator<Integer> cmp = (a, b) -> Integer.compare(a, b);

2. Comparator umschreiben

Schreibe den NameComparator aus dem ersten Abschnitt als Lambda. Sortiere die Namen aufsteigend.

Die Implementierung von compare wird zum Lambda-Rumpf.

names.sort((a, b) -> a.compareTo(b));

3. Nach Länge sortieren

Sortiere eine veränderbare Liste von Strings zuerst nach Länge aufsteigend, bei gleicher Länge alphabetisch.

Vergleiche die Längen mit Integer.compare. Bei 0 vergleichst du die Strings.

names.sort((a, b) -> {
    int result = Integer.compare(a.length(), b.length());
    if (result == 0) return a.compareTo(b);
    return result;
});

4. Predicate

Erstelle ein Predicate<Integer>, das gerade Zahlen erkennt. Teste es mit 8 und 7.

Eine Zahl ist gerade, wenn der Rest bei Division durch 2 gleich 0 ist.

Predicate<Integer> even = number -> number % 2 == 0;
System.out.println(even.test(8)); // true
System.out.println(even.test(7)); // false

5. Consumer

Erstelle einen Consumer<String>, der einen Namen mit dem Präfix „Hallo “ ausgibt. Verwende ihn mit forEach.

Consumer liefert keinen Rückgabewert.

Consumer<String> greet = name -> System.out.println("Hallo " + name);
names.forEach(greet);

6. Function

Erstelle eine Function<String, Integer>, die die Länge eines Strings liefert. Rufe sie mit „Java“ auf.

Verwende apply, um die Funktion aufzurufen.

Function<String, Integer> length = text -> text.length();
System.out.println(length.apply("Java")); // 4

7. Supplier

Erstelle einen Supplier<ArrayList<String>>, der bei jedem Aufruf eine neue leere Liste erzeugt.

Ein Supplier benötigt keine Parameter. Verwende new im Lambda-Rumpf.

Supplier<ArrayList<String>> createList = () -> new ArrayList<>();
ArrayList<String> first = createList.get();
ArrayList<String> second = createList.get();
System.out.println(first == second); // false

8. Liste verändern

Erzeuge eine ArrayList aus „Anna“, „Bo“ und „Clara“. Entferne Namen mit weniger als drei Zeichen und wandle die übrigen in Großbuchstaben um.

removeIf benötigt eine Bedingung; replaceAll benötigt einen neuen Wert für jedes Element.

List<String> names = new ArrayList<>(List.of("Anna", "Bo", "Clara"));
names.removeIf(name -> name.length() < 3);
names.replaceAll(name -> name.toUpperCase(java.util.Locale.ROOT));
System.out.println(names); // [ANNA, CLARA]

9. Eigenes Interface

Verwende IntOperation aus dem Theorieabschnitt. Definiere ein Lambda, das den größeren Wert zurückgibt, und übergib es an calculate.

Math.max liefert den größeren int-Wert.

IntOperation maximum = (a, b) -> Math.max(a, b);
System.out.println(calculate(4, 9, maximum)); // 9

10. Employee: weitere Sortierregel

Verwende die Employee-Klasse. Sortiere nach Dienstjahren absteigend und bei Gleichstand nach Namen aufsteigend.

Vertausche für absteigende Reihenfolge die Argumente bei Integer.compare.

employees.sort((e1, e2) -> {
    int result = Integer.compare(e2.yearsEmployed, e1.yearsEmployed);
    if (result == 0) return e1.name.compareTo(e2.name);
    return result;
});

11. Fehler finden

Warum kompiliert dieser Code nicht?

int limit = 3;
Predicate<String> longer = text -> {
    text.length() > limit;
};
limit++;

Achte sowohl auf den Blockrumpf als auch auf die lokale Variable.

Im Block fehlt die Rückgabe; der Vergleich allein ist außerdem keine zulässige Ausdrucksanweisung. Durch limit++ ist die übernommene Variable nicht effektiv final.

int limit = 3;
Predicate<String> longer = text -> {
    return text.length() > limit;
};

12. Methodenreferenzen

Ersetze die Lambdas aus Aufgabe 5 (ohne Präfix), Aufgabe 6 und Aufgabe 7 durch passende Methodenreferenzen.

Verwende System.out::println, String::length und eine Konstruktorreferenz.

ArrayList::new verweist auf einen Konstruktor. Das Präfix aus Aufgabe 5 würde weiterhin ein Lambda oder eine passende eigene Methode benötigen.

Consumer<String> print = System.out::println;
Function<String, Integer> length = String::length;
Supplier<ArrayList<String>> createList = ArrayList::new;

13. Comparator.comparing verstehen

Schreibe die Sortierung aus dem Employee-Beispiel mit Comparator.comparing() und thenComparingInt() um. Erkläre, welches funktionale Interface das Lambda e -> e.name implementiert.

comparing benötigt eine Funktion zum Auslesen des ersten Sortierschlüssels; der zweite Schlüssel ist eine int-Eigenschaft.

e -> e.name entspricht Function<Employee, String>. Es liefert nur den Namen; comparing() erzeugt daraus den Comparator.

Comparator<Employee> cmp = Comparator
    .comparing((Employee e) -> e.name)
    .thenComparingInt(e -> e.yearsEmployed);
employees.sort(cmp);
